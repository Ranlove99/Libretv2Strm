# 打包 fnOS fpk

`scripts/pack-fpk.sh` 把 `libretv/` 的构建产物 + `libretv-fpk/` 的打包层，组装成 ARM / x86 两个 fpk。

## 一、准备 vendor 目录

fpk 要能离线跑，必须自带 Node 运行时和对应架构的 sharp 原生模块。脚本从 `$VENDOR_DIR/{arm,x86}/` 取这两样，目录结构与 fpk 内的 `app.tgz` 解包后一致：

```
.vendor/
├── arm/
│   ├── runtime/node-arm64/bin/node
│   └── server/node_modules/@img/
│       ├── sharp-linux-arm64/
│       ├── sharp-libvips-linux-arm64/
│       └── sharp-wasm32/
└── x86/
    ├── runtime/node-x64/bin/node
    └── server/node_modules/@img/
        ├── sharp-linux-x64/
        ├── sharp-libvips-linux-x64/
        └── sharp-wasm32/
```

两种做法：

**A. 从已发布的 fpk 里解出来**（最省事）

```bash
mkdir -p /tmp/old && cd /tmp/old
tar xzf libretv2strm-1.1.0-arm.fpk && tar xzf app.tgz
# 得到 runtime/ 与 server/，放到 .vendor/arm/ 下；x86 包同理
```

**B. 自己装**

- Node：从 <https://nodejs.org/dist/> 下载 `node-v22.x-linux-arm64` / `linux-x64` 的二进制，取 `bin/node`
- sharp：`npm i --os=linux --cpu=arm64 @img/sharp-linux-arm64 @img/sharp-libvips-linux-arm64`（x64 同理）

## 二、构建

```bash
cd libretv
npm ci
NODE_OPTIONS= DOCKER_BUILD=1 npm run build
```

`DOCKER_BUILD=1` 会让 `next.config.ts` 产出 `output: 'standalone'`。
`NODE_OPTIONS=` 清空是必要的——本机若有 `--require` 预加载会在构建时注入调试代码。

改版本号要改**两处**：`libretv-fpk/manifest` 的 `version`，和 `libretv/package.json` 的 `version`。
后者经 `next.config.ts` 的 `env.APP_VERSION` 在**构建时**注入，`/api/status` 读的是它；只改 manifest 不改 package.json，网页里会显示旧版本。

## 三、打包

```bash
VENDOR_DIR=.vendor bash scripts/pack-fpk.sh
```

产物在 `dist/`：

```
libretv2strm-1.1.0-arm.fpk
libretv2strm-1.1.0-x86.fpk
SHA256SUMS.txt
```

## 四、脚本内置的校验

任何一条不通过就中止，避免打出装不上的包：

- `app.tgz` 顶层必须是 `server runtime ui config`，不能多套一层 `app/`
- `wizard/{install,upgrade,config,uninstall}` 四个文件都存在
- **不存在** `wizard/wizard/`（嵌套会让 fnOS 整页向导不渲染，装完没有密码界面）
- `wizard/install` 含 `wizard_password` 字段
- `cmd/main` 含空密码放行逻辑
- Node 运行时架构与包名一致（`file` 判断 ELF aarch64 / x86-64）
- `manifest.checksum == md5(app.tgz)`
- `.next/static` 里能 grep 到本版新增文案（防止误用旧 `.next`，新功能静默退回）

## 五、踩过的坑

**`cp -r wizard/ wizard/` 会生成 `wizard/wizard/install`**
fnOS 找的是 fpk 顶层的 `wizard/install`，嵌套一层就整页不渲染——表现为「安装时没有设置密码界面」。必须用 `cp -r wizard/. dest/wizard/`。

**`app.tgz` 多套一层 `app/`**
`tar czf app.tgz app/` 会把所有东西塞进 `app/` 前缀，fnOS 找不到 `server/`，应用起不来。要在 approot 目录内 `tar czf app.tgz server runtime ui config`。

**Node 运行时目录名**
只认 `node-arm64` / `node-x64`。`node-linux-arm64`、`node`、`node-v22-arm64` 都不行，启动时会报「未找到适配 aarch64 架构的 Node.js 运行时」。

**改了版本号但网页还是旧版本**
`APP_VERSION` 是构建时注入的，改完 `package.json` 必须重新 `next build`，否则 `.next` 里还是旧值。

**`du -h` 看两个包体积差很大**
macOS 的块大小导致小文件多的包虚高，用 `ls -l` 看字节数才准。

**STRM 中继模式的端口**
`cmd/main` 里 `STRM_LOCAL_PORT` 默认跟随 `PORT`。若在反向代理后改过端口，中继地址会拼错，`.strm` 里的地址要能对上实际可访问的端口。
